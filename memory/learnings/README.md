# Learnings

Use this folder for verified lessons that can improve future work: a confirmed cause of a recurring failure, a validated approach, or a useful check discovered during a task. Follow the shared [memory guidance](../README.md).

Read relevant lessons before working on a similar problem. Add a lesson when evidence supports it and the takeaway is reusable. Keep untested ideas in the active task note until verified.

Use a descriptive filename such as `configuration-validation.md` and include:

```markdown
# Lesson

- Applies when:
- Last verified: YYYY-MM-DD

## Observation
What happened and under which conditions.

## Evidence
The check or result that supports the lesson, with source links.

## Future action
What to do when those conditions occur again.

## Limits
When the lesson does not apply or needs verification again.
```

Update an existing lesson when new evidence changes it; retire disproven or obsolete advice. Keep entries concise and link to checks instead of copying logs. A lesson is evidence for a future decision, not a permanent rule. Turning it into a skill or agent instruction requires the authorization described in [AGENTS.md](../../AGENTS.md).
